# 南京地铁 1、2、3、4 号线 FPGA 自动售票系统

本工程位于 `"D:\FPGA26FALL\ticket_price"`，是一个独立 Vivado 工程，不会修改原来的 `D:\FPGA26FALL\vending`。设计参考了 `Nanjing-Metro-Inquiry-System` 的线路图建模思路，但把不适合放进 FPGA 的全图最短路计算移到数据生成阶段完成。FPGA 运行时只需根据两个站点编号读取 BRAM 中的最短累计距离，再按票价分段组合逻辑得到票价，因此查询延迟短、资源占用较小。

## 已实现功能

系统支持两种购票入口。KEY1 进入手动票价模式，适合乘客已经知道票价的情况；KEY2 进入自动查询模式，依次选择起点线路、起点站、终点线路和终点站。

自动查询覆盖本工程数据文件中的 1、2、3、4 号线。换乘站按站名合并为同一图节点，PC 端生成脚本使用 Dijkstra 算法计算 104 个唯一站点之间的全部最短累计距离，并将对称距离矩阵压缩为 5356 项三角矩阵 ROM。确认终点后，FPGA 从 ROM 读取最短距离并实时换算票价。

查询票价后可选择 1 至 9 张票。付款阶段支持 1 元、5 元、10 元和 20 元面额；当投入金额达到应付金额时，系统自动出票并一次性显示找零。付款过程中按 KEY4 可取消交易，已投入金额会一次性显示为退款金额。

## 面板操作

| 所在界面 | KEY1 | KEY2 | KEY3 | KEY4 |
| --- | --- | --- | --- | --- |
| 初始模式选择 | 进入手动票价模式 | 进入自动查询模式 | 无操作 | 无操作 |
| 手动票价 | 确认票价 | 返回初始界面 | 票价加 1 | 票价减 1 |
| 起点或终点线路 | 选择 1 号线 | 选择 2 号线 | 选择 3 号线 | 选择 4 号线 |
| 起点或终点站 | 确认站点 | 返回线路选择 | 下一站 | 上一站 |
| 票数选择 | 确认票数并进入付款 | 取消并返回初始界面 | 票数加 1 | 票数减 1 |
| 付款 | 按当前拨码面额投入一次 | 无操作 | 无操作 | 取消并退款 |

选择线路后，只保留所选线路的数字并闪烁两次，其余三个线路数字全部熄灭，此时 LED1 至 LED4 也保持熄灭。确认一个站点后，四个 LED 同时闪烁两次。出票找零状态下，购买几张票，四个 LED 就同步闪烁几次；每次点亮 0.25 秒、熄灭 0.25 秒，相邻两次闪烁的起始间隔固定为 0.5 秒。找零至少显示约 3 秒，购买票数较多时会保持到 LED 完成全部闪烁。取消退款状态下 LED1 和 LED4 点亮约 1 秒。板载 LED 按低电平点亮实现，顶层参数 `LED_ACTIVE_LOW` 默认值为 `1`。

SW4 是低有效复位开关。付款时，SW3、SW2、SW1 的编码如下。

| SW3 SW2 SW1 | 本次投入金额 |
| --- | ---: |
| 001 | 1 元 |
| 010 | 5 元 |
| 011 | 10 元 |
| 100 | 20 元 |
| 其他组合 | 忽略，不记入金额 |

使用时先拨好面额，再按一次 KEY1，表示投入一次该面额。系统只在按键确认沿记账，不会因为拨码保持不变而重复加钱。

## 数码管显示约定

初始界面最左位显示 `1`、最右位显示 `2`，分别提示 KEY1 手动模式和 KEY2 自动模式。线路选择界面显示 `1234`。

站点选择界面最左位显示线路号，最右三位显示站点代码。代码按 `线路号 × 100 + 线路内序号` 编排，例如 `101` 是 1 号线第 1 站，`418` 是 4 号线第 18 站。站名、站点代码和下一段距离的完整对照表在 `data/station_codes.csv` 中。

票数选择界面左侧两位显示单张票价，最右位显示票数。确认票数后，付款界面只显示 `总价三位 + 中间两位空白 + 已付三位`。例如总价 6 元且已经投入 5 元时显示为 `006  005`；每次投入后，右侧已付金额会实时累加。

出票界面至少停留约 3 秒，其他数码管全部熄灭，仅在最右三位显示找零金额；若票数对应的 LED 闪烁尚未结束，找零会继续显示到闪烁完成。退款界面最右三位显示退款金额。

## 票价规则

票价逻辑严格按照提供的距离—票价图实现。

| 最短累计距离 | 单程票价 |
| --- | ---: |
| 不超过 4 km | 2 元 |
| 大于 4 km 且不超过 9 km | 3 元 |
| 大于 9 km 且不超过 14 km | 4 元 |
| 大于 14 km 且不超过 21 km | 5 元 |
| 大于 21 km 且不超过 28 km | 6 元 |
| 大于 28 km 且不超过 37 km | 7 元 |
| 大于 37 km 且不超过 48 km | 8 元 |
| 大于 48 km 且不超过 61 km | 9 元 |
| 大于 61 km | 每增加不足或达到 15 km 加 1 元 |

同站进出距离为 0，按照上述规则显示最低票价 2 元。

## 数据版本和更新方法

当前可复现数据包含 1 号线 32 站、2 号线 30 站、3 号线 31 站、4 号线 18 站，共 111 个线路内站点记录，合并换乘站后为 104 个唯一站点。当前数据的最大最短距离为 53560 m，最大票价为 9 元。

3 号线已更新为开通三期延长段后的 31 站版本，在秣周东路之后新增 `330 上秦淮西` 和 `331 秣陵`。公开工程资料给出延长段全长约 3.3 km，其中秣周东路至上秦淮西约 1.6 km；本工程据此采用可复现的 `1.600 km + 1.700 km` 区间拆分。以后若取得运营方发布的精确站中心里程，只需修改 `data/metro_lines.txt` 中这两段距离并运行以下命令，脚本会自动重建站点映射、站点表和距离 ROM。

```powershell
python scripts\generate_metro_data.py
```

数据更新后需要重新创建或刷新 Vivado 工程，再跑仿真和实现，以免工程继续使用旧 ROM。

可用独立的 Floyd-Warshall 校验器逐项检查 CSV、Verilog 映射、元数据以及全部 5356 个距离 ROM 条目。该校验器与生成器使用不同的最短路算法。

```powershell
python scripts\verify_metro_data.py | Tee-Object reports\data_verification.log
```

## 工程结构

| 路径 | 作用 |
| --- | --- |
| `src/` | 顶层状态机、按键消抖、LED 闪烁、最短距离 ROM 查询、票价计算、BCD 转换和数码管扫描 RTL |

| `scripts/` | 数据生成、独立数据校验、工程创建、仿真和 bitstream 构建脚本 |
| `reports/` | 仿真、时序、资源、DRC 和 methodology 签核报告 |
| `output/ticket_price_top.bit` | 已验证构建的可下载 bitstream |

## 复现与验证

本工程使用 Vivado 2024.1 和器件 `xc7a75tfgg484-2`。在工程根目录运行以下命令可从源文件重新创建 `.xpr`。

```powershell
& 'D:\Vivado\Vivado\2024.1\bin\vivado.bat' -mode batch -source scripts\create_project.tcl
```

运行完整行为仿真使用以下命令。

```powershell
& 'D:\Vivado\Vivado\2024.1\bin\vivado.bat' -mode batch -source scripts\run_sim.tcl
```

仿真报告出现 `TEST_PASS` 表示硬件距离查询已穷举通过全部 5460 个无序站点组合，其中包含 104 个同站查询和 5356 个异站查询；低有效 LED、四条线路映射、换乘别名、只显示所选线路数字并闪烁两次、3 号线延长站、站点确认 LED 闪烁、最短距离、全部票价边界、票数、总价与已付显示、延长的单独找零显示、按出票张数固定间隔闪烁和取消退款也均已通过。

重新综合、布局布线和生成 bitstream 使用以下命令。

```powershell
& 'D:\Vivado\Vivado\2024.1\bin\vivado.bat' -mode batch -source scripts\build_bitstream.tcl
```

本次签核结果为全部 5356 个距离 ROM 条目通过独立 Floyd-Warshall 算法复核，硬件行为仿真穷举通过全部 5460 个无序站点组合，并逐项验证 1 至 9 张票的 LED 闪烁次数与固定间隔。普通 DRC 为 0 条违规，methodology 为 0 条违规，全部用户时序约束满足。实现后使用 675 个 Slice LUT、278 个 Slice Register 和 4.5 个 Block RAM Tile。输出 bitstream 的 SHA-256 为 `51A281071F29126A714E8B0E5CC5D7E0315BC38F4A949DE5B0F90A41C55487B1`。

## 上板前需要确认的两项

第一项是 LED 极性。约束文件使用与该 XC7A75T 板卡相匹配的 LED1 至 LED4 引脚，当前已根据实物验证改为默认低电平点亮，即 `LED_ACTIVE_LOW=1`。

第二项是 3 号线延长段里程来源。新增站名和 3.3 km 总里程来自公开工程与开通资料，两段距离采用上述可复现拆分；如获得更精确的运营站间距，应重新生成 ROM 和 bitstream。
